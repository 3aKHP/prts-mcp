## 关键决策：rmcp 3.5.1 → 薄适配（10-research 风险表预置路径）

`examples/rmcp_probe.rs` 以与 oracle 相同身份运行 rmcp 3.5.1 StreamableHttpService，实测与 wire 基准的差异：

| 观察 | oracle | rmcp 3.5.1 |
|---|---|---|
| legacy POST 响应 | `event: message\ndata:…`，无 priming | priming 事件（`data:\nid: 0\nretry: 3000`）+ 无 event 名 + SSE 事件 id（`id: 1/0`）+ 额外头（cache-control/x-accel-buffering） |
| 未知会话 | 404 + JSON-RPC `-32002` + 项目文案 | 404 纯文本 `Not Found: Session not found` |
| server/discover | `supportedVersions:["2026-07-28"]`、application/json | 5 个版本、SSE+priming |
| modern 响应格式 | application/json | SSE |
| modern 坏信封文案 | 项目化 `data.envelope.missing` | 不同 message 与 data 形状 |
| 失效 initialize 恢复 | 项目定制（剥离旧 id 重建会话） | 无此语义 |

结论：rmcp 传输层无法在配置面上复现 Express+SDK v2 的 wire 指纹；按风险表走「最小复现，评估薄适配」——产品采用 `src/protocol` 的薄 JSON-RPC 适配（axum + 逐字 golden schema），rmcp 保留为 dev-dependency + 探针证据可复现。这不是「大幅私有协议栈」分支：适配面只有 oracle 实际暴露的 initialize/initialized/tools-list/tools-call/server/discover 与四类传输错误，SDK 的 resources/prompts/sampling/auth 等能力 oracle 本就未暴露。

## 失败/未执行项（诚实清单）

- **D-P1-INPUT-SURROGATE（登记决策项，非静默差异）**：`{"chapter":"\ud83d"}` 类孤立代理对 —— Bun 接受并在响应中回显 `\ud83d`（200），serde_json 拒收整个请求体（400）。证据 `contracts/wire/supplemental/lone-surrogate-boundary.json`。是否实现 UTF-16 容忍 JSON 层属输入支持集变更，按 01 需维护者决策；当前无差分案例依赖该输入。
- Express 对坏 JSON 请求体返回 HTML 错误页（wire transport-edges 已存证）：薄适配回 JSON `-32700` 家族。非差分案例；登记为已知框架工件差异（D-003 邻域），如后续需要可升格为案例。
- GET /mcp 持流在 Rust 端以「永不开口的 SSE 流」实现（无订阅推送语义，oracle 亦无）；未做长时挂接差分。
- modern 通道 header（x-prts-output-channel）仅 wire 采证（era-boundary 流），差分案例覆盖了 query 通道；P3 补 header 通道差分案例时一并覆盖。
- 批处理（数组 body）跨 era 混发、PUT 之外的非常规方法组合等未逐项差分（wire 有 PUT/GET/DELETE 基准；案例集按 06 覆盖矩阵取舍）。
