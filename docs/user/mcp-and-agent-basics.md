# Agent 与 MCP 零基础入门指南

本文面向第一次接触 **Agent（智能体）** 与 **MCP（Model Context Protocol，模型上下文协议）** 的明日方舟同人创作者、剧情考据党与普通玩家。

如果你平时只用过网页版 AI 聊天（如 ChatGPT、DeepSeek、Claude 网页端），想知道“为什么装上 PRTS-MCP 就能让 AI 查方舟设定和剧情”、“我该下载什么软件、怎么用起来”，请花 3 分钟读完本文。

- 已经了解基本概念、准备直接配置软件？请跳至[客户端接入与快速上手指南](quick-start.md)。
- 已经配好软件、想看怎么组合查询设定与剧情？请参阅[工具使用与同人创作工作流指南](tools-guide.md)。

---

## 1. 一句话看懂：普通 AI 聊天 vs. 接入 PRTS-MCP 的 Agent

许多创作者在网页版 AI 里问明日方舟问题时，都遇到过所谓的**“AI 幻觉（一本正经地胡说八道）”**：
- 问它“《怀黍离》里黍和绩的对话原文”，它自己编造了一段看似很像但完全不存在的台词；
- 问它“某位新干员二技能专精三的回转和倍率”，它给出了一串凑出来的数字。

**为什么会这样？** 因为大模型在没有查阅可靠资料时，可能会靠“训练时的模糊记忆”来回答。

而 **Agent + PRTS-MCP** 的组合，就是给这位“会写文章但记不住细节的撰稿助手”配上一座**可更新的方舟资料库**：

| 核心概念 | 用明日方舟同人创作打比方 | 它在实际使用中负责什么？ |
| --- | --- | --- |
| **大语言模型（LLM）** | **你的“同人撰稿与分析助手”**（如 Claude、DeepSeek、GPT） | 负责理解你的提问、决定该查什么资料，并在拿到真实资料后为你整理考据结论或润色同人文。 |
| **MCP（模型上下文协议）** | **行业通用的“USB 扩展接口”** | 一套统一的通信标准，让不同的桌面 AI 软件都能直接插上 PRTS-MCP，而不需要为每个软件单独开发插件。 |
| **PRTS-MCP（本项目）** | **插在 USB 口上的“方舟离线数据库 + PRTS 维基检索器”** | 默认提供 **24 个专用查询工具**（查干员档案、全语音、技能面板、关卡敌情、物品、全量剧情台词、PRTS 词条与立绘），**本身不负责聊天，负责返回游戏原文、查询结果与剧情梗概**。 |
| **MCP 客户端** | **你电脑上打开的“工作台软件”**（如 Chatbox、Cherry Studio、Claude Desktop、Cursor 等） | 把“大模型”和“PRTS-MCP 工具箱”连接在一起的软件。接到模型的工具请求后，软件调用 PRTS-MCP 查表并把结果塞回对话中。 |
| **Agent（智能体）** | **会自己查资料的助手** | 在模型与软件的配合下，根据你的要求选择工具、查看结果，再决定是否继续查询，直到整理出回答。 |

### 一次真实提问的幕后流程

当你在客户端里输入：*“帮我查一下能天使的干员密录讲了什么，顺便核对一下她的晋升语音。”*

```text
1. 你在客户端提问 ──▶ 2. 大模型发现需要查资料，自动发出工具请求：
                        - 调用 get_operator_memoirs(name="能天使") 拿到密录 story_key
                        - 调用 read_story(...) 读取密录完整台词原文
                        - 调用 get_operator_voicelines(name="能天使") 读取全语音记录
                     ──▶ 3. PRTS-MCP 从本地数据包取出原文返回给模型
                     ──▶ 4. 大模型基于原文为你总结剧情，你可以对照工具结果核对引用
```

在支持工具调用且已启用 PRTS-MCP 的客户端里，你**不需要手动输入代码或工具名**——用自然语言提要求，模型就可以选择合适的工具来用。

## 2. 怎么选适合你的软件与接入模式？

### 2.1 第一步：选一个顺手的 MCP 客户端软件

网页浏览器里的普通聊天页面通常无法直接运行本地插件，你需要先在电脑上安装一个支持 MCP 的客户端软件：

| 你的使用习惯与现有条件 | 推荐客户端 | 特点说明 |
| --- | --- | --- |
| **有 DeepSeek / OpenAI / 硅基流动 / OpenRouter 等 API Key，想用来日常聊天、查设定、写同人** | **Chatbox**、**Cherry Studio** | 纯图形界面，支持接入几乎所有主流大模型 API，在设置里填一下 MCP 命令或网址就能用，对非程序员最友好。 |
| **开通了 Claude 官方会员（Pro / Max / Team）** | **Claude Desktop**（桌面客户端）或 **Claude Code**（命令行/IDE） | Anthropic 官方出品，对 MCP 工具的连续组合调用（比如“先搜目录 → 再读章节 → 再查角色出场”）理解能力极强。 |
| **喜欢用编辑器写长篇小说、管理本地 Markdown 设定集** | **VS Code**（安装 **Roo Code** 或 **Cline** 扩展）、**Cursor** | AI 不仅可以调用 PRTS-MCP 查完干员档案和剧情，还能直接把整理好的考据笔记或小说草稿写入你电脑里的文档。 |

### 2.2 第二步：看懂两种运行方式——`stdio` 与 `HTTP` 选哪个？

在阅读[快速上手指南](quick-start.md)时，你会看到 **`stdio` 模式**和 **Streamable HTTP 模式**两个词。它们的区别其实非常简单：

| 运行模式 | 通俗解释 | 谁该选它？ |
| --- | --- | --- |
| **本地 `stdio` 模式**<br>（最推荐个人使用） | **“随开随用模式”**：你在客户端设置里填启动命令（或文件路径）与环境变量，原生程序须设 `PRTS_TRANSPORT=stdio`。客户端负责在后台启动和结束进程，不需要你手动黑框运行。 | **个人创作者与普通玩家**。只要在一台电脑上自己用，优先选 `stdio` 即可。 |
| **常驻 `HTTP` 模式**<br>（适合进阶/共享） | **“本地/私人网站模式”**：你先自己把 `prts-mcp` 作为一个后台服务运行起来，它会提供一个类似 `http://127.0.0.1:3000/mcp` 的网址；然后你在各个客户端里直接填入这个网址即可连接。 | 适合**同时打开多个客户端共用一份缓存**、部署在家里 NAS/云服务器上供手机或平板远程连接、或与创作社团伙伴共享。 |

### 2.3 本地 `stdio` 模式的三种安装途径怎么挑？

PRTS-MCP 的公开安装包都**已经内置了完整的离线游戏数据（干员、关卡、物品、剧情）**，你可以按电脑现有环境三选一：
1. **直接下载预编译压缩包（零依赖，最适合纯新手）**：不需要装 Node.js，也不需要装 Docker。去 Release 页面下载对应系统的 `.tar.gz`（macOS/Linux）或 `.zip`（Windows），解压后把里面的 `bin/prts-mcp`（Windows 为 `bin\prts-mcp.exe`）路径填进客户端，并在环境变量 `env` 中加上 `"PRTS_TRANSPORT": "stdio"`。完整配置见[快速上手指南](quick-start.md)。
2. **使用 `npx`（适合电脑已装 Node.js `>= 22` 的用户）**：无需手动下载解压，客户端会自动通过 `npx` 拉取并运行。
3. **使用 Docker（适合电脑已装 Docker Desktop 的用户）**：一行 `docker run -i --rm ...` 命令即可运行，环境完全隔离。

## 3. 配好之后的“基本操作”长什么样？

当你照着[快速上手指南](quick-start.md)把配置填进客户端并保存后，日常使用只有以下四步：

### 第一步：确认工具箱已亮起
在客户端的聊天输入框附近（或设置面板的 MCP 列表里），确认 `prts_wiki` 显示已连接，点开可以看到默认的 **24 个可用工具**（如 `get_operator_archives`、`read_story`、`search_prts` 等；禁用立绘时为 23 个）。能看到工具列表，说明客户端已连上服务；接下来实际查一次资料，确认模型能调用工具并收到结果。

### 第二步：像平时一样用中文提问
你**不需要**背诵任何英文工具名。直接对 AI 说人话即可，例如：
- *“帮我查一下阿米娅精英二 40 级的面板数值，以及二技能专三的描述。”*
- *“帮我看看主线或者活动里，‘凯尔希’和‘特蕾西娅’同场对话的章节有哪些？”*
- *“帮我在 PRTS 维基上搜一下‘源石技艺’词条的目录，先别读全文，把章节列表列给我看看。”*

### 第三步：处理弹窗确认（Approve / Allow）
触发工具调用时，部分客户端会按权限设置弹出确认框，例如：
> *“是否允许运行工具 `prts_wiki: get_operator_basic_info`？”*

这是客户端的权限确认机制，用来让你知晓 AI 正在查阅什么数据。确认后点击 **Allow（允许）** 即可；如果客户端提供 **“始终允许此工具 / Always allow”**，可以用它减少后续重复确认。模型是否继续查询，仍取决于你的任务和它的工具调用能力。

### 第四步：掌握“省流又精准”的提问小窍门
方舟的一整个活动剧情往往有五六万字，如果直接对 AI 说*“把怀黍离所有剧情全文读一遍”*，AI 可能会一口气把几万字塞进对话窗口，既慢又费 Token。更聪明的问法是**让 AI 先看目录和梗概，再精读重点章节**：
- ✅ **推荐问法**：*“先帮我列出活动 `act31side`（怀黍离）的章节列表和每章梗概，我看看哪几章有黍的核心剧情，然后再让你读那几章的完整台词。”*
- 更多考据连招请参阅[工具使用与同人创作工作流指南](tools-guide.md)。

## 4. 新手最常遇到的 4 个疑问（FAQ）

### Q1：修改客户端的 JSON 配置文件时，为什么保存后报错或没反应？
- **检查标点符号**：JSON 配置文件里的引号 `"`、冒号 `:`、逗号 `,` 必须是**英文半角符号**，且最后一项后面不能多写逗号。
- **注意 Windows 路径斜杠**：如果在 Windows 的 JSON 文件里填写本地 `prts-mcp.exe` 的路径，请统一把路径分隔符写成**正斜杠 `/`**（例如 `"D:/prts-mcp/bin/prts-mcp.exe"`），不要直接粘贴带单反斜杠的 Windows 资源管理器路径。
- **重启生效**：部分桌面客户端（如 Claude Desktop）修改配置文件后，需要**彻底退出并重新打开客户端软件**才会重新加载。

### Q2：使用 PRTS-MCP 需要付费吗？需要科学上网（代理）吗？
- **完全免费开源**：PRTS-MCP 本身没有任何收费项目，也不需要注册账号。你在客户端里接入的大语言模型是否收费、如何收费，取决于所选服务；API 通常按输入和输出的 Token 用量计费，Token 不等同于字数。
- **网络要求**：安装包内已经自带了干员、技能、关卡、物品与剧情的离线备用数据，**哪怕断网也能查干员档案和剧情**（联网时它会在后台自动从 GitHub 同步最新活动数据）。只有 `search_prts`、`prts_page` 与默认在线立绘需要实时访问国内可直接连接的 `https://prts.wiki`。

### Q3：为什么我用 `prts-mcp` 原生程序配置了本地 `stdio`，客户端却提示连接断开？
- 这是最常见的小细节：`prts-mcp` 主程序为了照顾服务器用户，直接双击或无参数运行时默认启动的是 **HTTP 网页服务模式**。
- 当你在本地客户端里以 `stdio` 子进程方式配置它时，请务必按[快速上手指南](quick-start.md)的示例，在环境变量 `env` 中加上 `"PRTS_TRANSPORT": "stdio"`（或者直接使用固定为 stdio 模式的 `prts-mcp-ts-stdio` 命令）。

### Q4：AI 有时候为什么没主动调用工具，而是自己瞎猜？
- 先确认当前模型支持工具调用，且客户端已为这次对话启用 PRTS-MCP。条件都满足时，可以在提问里带一句**“请使用 PRTS 工具查询”**或**“请先查表核实”**。再看看客户端的工具调用记录，确认它实际查了什么；只在回答里声称“已经查询”，不代表真的调用过工具。
