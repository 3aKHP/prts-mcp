# M2B npm 包装验收

日期：2026-10-13。PR：[#231](https://github.com/3aKHP/prts-mcp/pull/231)。实现检查点：d5f09772f1d8e087eda1c7a7701bff9c1372fabf；后续收尾更新仅补充文档，最终合并以 PR 最终 HEAD 的 CI 和独立复审为准。

## 已完成

prts-mcp 新入口与 prts-mcp-ts 的三个兼容命令使用同版共享 runtime、data 和原生平台包。Node 仅定位并启动 Rust，不承载业务，不引入 JS/TS 回退。正常 npm 安装取得预编译产物，不需要用户配置 C/Rust 工具链或 Bun。入口默认传输与既有命令契约保持。[包装规则与复现步骤](../NPM-DISTRIBUTION.md)。

备用数据独立固定 AKDP Release、manifest、源版本及三包大小/SHA，复用 Rust 的文件/剧情引用检查和安全解压，解析全部 JSON，记录 BUNDLE.json 和 4,008 个数据文件的校验值。用户完整数据优先，安装数据只供备用读取。原生包保留构建/ABI 记录、校验清单、NOTICE 和实际第三方许可文件；打包成员及安装后的全部哈希/许可引用均检查。

数量差异来自 Unix 三种信号、Linux musl 拒绝诊断和 Windows 两种用户目录解析检查。验收执行真实全局双入口安装、真实全局命令 shim、两个入口的干净缓存 npx、保持锁文件不变的干净缓存 npm ci、同项目共享依赖、空用户目录离线备用查询、旧/新 MCP 协议及冻结输出、非零退出、版本错配和真实 omit=optional 安装诊断。Unix 信号转发和 Windows 强制结束 Node 父进程后均确认没有遗留 HTTP listener。

每个平台产生五个真实 tarball；npm-evidence.json 和 npm-runtime-evidence.json 随 CI artifact 留存。只读 loopback registry 用于安装验证，外平台仅模拟锁文件解析元数据；异平台执行结论来自对应原生 runner，不来自模拟选择器。所有 25 个下载 tarball 另行核验 SHA256、npm SHA512 integrity、文件数量/总大小、原生及数据校验清单和许可引用。BUILD 均指向干净的上述实现检查点。

完整验证还通过 215 项 Rust 测试、fmt/clippy、384/384 冻结差分、生命周期链、3,276 个原生正则 ASAN 案例和 128 文件的独立 Cargo 源码包构建。

## 审查与修正

独立只读审查分别覆盖包装/安装和原生生命周期/数据边界。包装审查发现原生许可目录未进入 npm files 白名单，已修复并加入真实打包成员及安装后校验。最终无未解决 Blocking/Should-fix。Bot 故障按维护者指示忽略，不宣称 Bot 通过；维护者授权全部完成后合并。

Windows 早期 probe 在三分钟后退出且原日志没有阶段信息。补充阶段/错误日志，并将 Windows npm 完整数据安装等待预算设为十分钟后，所有断言通过；日志显示首次双入口安装至 profile 完成约 185 秒，后续两个 npx 各约 66 秒、install 加 npm ci 约 131 秒。旧日志不足以唯一定位原失败阶段；较长预算有实际文件安装耗时依据，不代表用户侧性能保证，也不会将超时计为通过。

另有本机 Windows 经 WSL UNC 路径复制测试 fixture 时遗漏文件的复现问题；诊断确认四份必需文件不存在，Rust 正确回退到真实备用数据。完整复制后八项安装入口 profile 检查通过；该辅助复现不代替五平台 CI，也不视为 M4 真客户端 E2E。

运行时审查保留一个非阻断后续硬化项：Windows watcher 线程打开父进程 handle 前存在极窄 PID 复用窗口。已打开的 handle 固定进程身份；提前启动取消可在后续单独评估。本阶段不宣称覆盖该窗口。
