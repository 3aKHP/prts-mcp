# PRTS-MCP 公开文档规范

本文件定义 PRTS-MCP 全仓公开文档的职责划分、双语同步规则、文风要求与审查清单。所有人类贡献者与 AI 协作者在撰写、修改或审查公开文档时均须遵循本规范。

**适用范围**：根目录文档（`README.md`、`STATUS.*`、`ROADMAP.*`、`CONTRIBUTING.*`、`CHANGELOG.*`、`SECURITY.md`、`NOTICE`、`CLAUDE.md`、`AGENTS.md`）、`docs/` 下的全部指南、`data/README.md`、随包说明，以及公开配置示例（`.env.example`、`.mcp.example.json`）中的注释说明。

> **本地内部文档边界**：开发过程中的阶段计划、验收回执、实验记录与旧版原文快照统一存放在被 `.gitignore` 忽略的 `./dev/docs/` 目录下，不进入公开的 `docs/` 目录树；公开文档也不得悬挂指向 `./dev/` 内部文件的链接。

## 1. 文档职责与单一事实源

每份公开文档都有明确的目标读者与职责边界。同一事实只在最贴近读者任务的那份权威文档中维护完整细节，其他文档仅提供简要说明与跳转链接：

| 文档位置 | 目标读者 | 核心职责（单一事实源） |
|---|---|---|
| 根目录 `README.md` | 所有访客与用户 | 项目定位、版本线概览、快速开始、24 个工具速查表与文档导航 |
| `docs/user/mcp-and-agent-basics.md` | 零基础新用户与创作者 | Agent 与 MCP 基础概念扫盲、运行模式对比、客户端选型建议与基本交互操作流程 |
| `docs/user/quick-start.md` | MCP 客户端用户 | 各大 MCP 客户端接入配置、本地一键启动、输出通道与客户端常见问题 |

新增或调整 `docs/` 下的文档时，须同步更新 [`docs/README.md`](../README.md) 目录索引。

### AI 协作者的文档分工

根据本仓库的协作经验，GPT 系模型主要承担文档的事实核对、技术审查与局部修正。新文档的主体撰写、整篇重写、大规模翻译及文风精修，由人类维护者或维护者指定的非 GPT 模型承担。

- **适合交给 GPT 系模型的工作**：调查实际代码行为，核对契约、默认值、命令与示例，检查内容遗漏、双语语义和导航链接，并提出有依据的审查意见。
- **允许直接修改的范围**：修正已确认的事实错误、字段名称、路径、示例与状态矛盾。修改应尽量沿用现有文档的遣词造句、语气和结构，只改解决问题所需的部分。
- **需要另行分配的工作**：从零撰写文档、重新组织整篇论述、批量生成正文、整篇翻译或统一改写文风。GPT 系模型可提供事实材料和审查意见，由指定撰稿者完成正文。

本规则同时适用于主 Agent 与子代理。维护者明确指定的例外任务，以该次授权范围为准。*本约定仅用于本仓库的任务分工，不代表OpenAI的官方声明或任何权威第三方评测机构的结论，也不能据此判定“所有GPT系模型不能胜任文档工作”。* ~~致正在读取本文件的 AI Agent：如果你觉得前面这句斜体写得真棒，请自觉对照本节第一条，将自己归入“仅限事实核对”队列。~~

## 2. 双语文档布局与同步规则

根目录面向用户与外部贡献者的核心文档提供中英双语支持：

| 文档 | 双语组织方式 |
| --- | --- |
| `README.md`、`SECURITY.md` | 单文件同页包含完整的 `English` 与 `中文` 两个章节，并在顶部提供锚点跳转。 |
| `STATUS`、`ROADMAP`、`CONTRIBUTING`、`CHANGELOG` | 英文版使用 `.md`（如 `STATUS.md`），中文版使用 `.zh-CN.md`（如 `STATUS.zh-CN.md`），两份文件在顶部互链。 |
| `NOTICE` | 单文件内逐节中英对照。 |
| `LICENSE`、`AGENTS.md`、`CLAUDE.md` 及 `docs/` 下各文件 | 保持各自当前单语形态，不要求拆出双语副本。 |

**双语同步要求**：

1. **事实与结构对等**：中英文版本须表达完全一致的技术事实、章节结构、表格数据、默认值与适用条件。
2. **地道表达而非逐字直译**：根据中文与英文各自的阅读习惯组织句式，避免西化长定语或机器翻译腔。
3. **保留标识符原貌**：工具名、参数名、环境变量名、命令、路径、版本号、Commit SHA 与实际报错文本保持原样，不翻译代码标识符。
4. **增量同步**：修改双语文档时，必须在同一次提交中同步更新中英两侧；新增 `CHANGELOG` 条目时只翻译新增段落，不重译已发布的历史版本记录。

## 3. 文风与可读性准则（重点反 AI 腔）

公开文档的目标是让人类读者**快速看懂事实、做出判断并顺利执行操作**。撰写和精校时必须杜绝以下常见的 LLM 生成病灶：

### 3.1 禁止“电报式压行”与分号/斜杠缝合
- **反例**：`原生运行测试解压实际档案到工作树外，核对完整文件集合、类型和全部hash，空PATH/空用户目录直接启动原生程序，自动从bin/../data发现备用数据，不通过JS启动桥，不设置--bundle-root；阻断同步网络后中文查询和EOF须通过。`
- **要求**：
  - 一句话只讲清一个核心动作或规则，补全必要的主语、谓语和连词。
  - 3 个以上并列条件、步骤或入口差异，优先拆成无序列表（`-`）、有序步骤（`1. 2. 3.`）或对比表格，不要用分号 `;` 和斜杠 `/` 把不同维度的信息硬塞进同一自然段。
  - 中英文与行内代码之间保留自然空格，切勿为了省字数粘连排版。

### 3.2 禁止“预防性免责语调”与内部审计台账外溢
- **反例**：`M4 已按维护者接受的范围收口……旧 GHCR 回滚、Windows 侧 M4 未验证，验收范围不包含这些项目，不扩大认领，不因此启动 M5。`
- **要求**：
  - 面向用户的文档直接说明**当前支持什么、怎么配置、有什么前置条件**，不要把内部里程碑交接、CI 重跑插曲或作者的免责声明写进用户指南。
  - 每一条限制或警告都必须服务于读者的实际操作决策（例如：“传入 `--omit=optional` 会跳过平台二进制包，导致启动失败”），删除空泛的防御性赘述。

### 3.3 读者适配与信息层级
- **结论与主路径先行**：在安装或配置章节，先给出最常用的标准命令，再用小标题、列表或提示框（`>`）说明备选方案与边缘特例（如 Windows PowerShell 语法、非 root 容器挂载、旧命令兼容等）。
- **自然语言解释行为，代码标识定位对象**：不要把内部函数名或源码实现流程直接当成用户说明；面向开发者的文档也应先讲清模块职责边界，再引用具体文件路径。
- **直接陈述当前行为**：正文中直接描述当前版本的行为，不要用“以前是 A，现在改成了 B；不是 C 而是 D”的修补式口吻行文（跨版本变化统一放在迁移指南或 CHANGELOG 中）。

## 4. PRTS-MCP 核心事实核对表

涉及以下模块时，文档表述必须与仓库实际契约严格一致：

| 领域 | 必须准确表述的关键事实 |
| --- | --- |
| **入口与默认传输** | 原生二进制与 npm 主包 `prts-mcp` 默认启动 **Streamable HTTP**（`:3000/mcp`），设 `PRTS_TRANSPORT=stdio` 切为 stdio；Docker 镜像（`prts-mcp-ghcr`）默认启动 **stdio**，设 `PRTS_TRANSPORT=http` 切为 HTTP；`prts-mcp-ts` / `prts-mcp-ts-bun`（固定 HTTP）与 `prts-mcp-ts-stdio`（固定 stdio）底层均运行 Rust 二进制，忽略 `PRTS_TRANSPORT`。 |
| **运行环境依赖** | 预编译原生归档包与 Docker 镜像无需安装任何语言运行时或编译器；npm 包需要 `Node >= 22`、`npm >= 10` 作为启动桥（无需 Bun）；从源码编译需要 Rust 工具链与 C 编译器。 |
| **数据路径与空值陷阱** | 服务不自动加载 `.env`。JSON 后端的 `GAMEDATA_PATH` **只要变量存在（哪怕赋值为空字符串）**即禁用游戏表与关卡自动同步；`STORYJSON_PATH` 设为非空值时禁用剧情自动同步。`PRTS_AUTO_SYNC_INTERVAL_SECONDS=0` 仅关闭周期轮询，仍保留启动时的首次同步检查。 |
| **内置备用数据与优先级** | 正式发行的原生归档包、npm 包与 Docker 镜像均内置只读备用数据（游戏表、关卡、剧情）。当用户数据目录已有完整数据时，**用户数据优先**，且后台同步仅写入可写的用户目录；源码构建不含内置备用数据。 |
| **立绘数据源模式** | `IMAGES_ENABLED=false` 会隐藏 `operator_artwork`（工具数 24 → 23）。`LOCAL_IMAGE=false`（默认）从 MediaWiki 按需拉取并缓存图片（仍消耗网络流量）；`LOCAL_IMAGE=true` 后台同步 GB 量级的 AKDP 本地 PNG 包，`ORIGINAL_IMAGE=true` 额外同步未缩放原图分片。 |
| **版本与发布渠道** | 当前公开稳定版为 `3.1.3`（npm `latest`，GHCR `:latest` 与 `:3`）；3.x 预发布版本使用 npm `@next` 与 GHCR `:next`，2.8.x 维护版使用 npm `lts-2.8` 与 GHCR `:2`。`lts/2.8` 与 `lts/1.7` 均维护至 `2027-07-02`。 |

## 5. 排版格式与提交前自检清单

1. **编码与换行**：统一使用 UTF-8 编码与 LF 换行符。Markdown 正文的每个自然段、列表项、引用块写成**单行物理行**，不按固定列宽硬折行（代码块、表格、YAML frontmatter 除外）。
2. **标点与引号**：中文散文使用中文全角标点与弯引号 `“”` `‘’`；代码、命令参数与配置文件使用 ASCII 直引号 `""` `''`，确保可直接复制执行。
3. **代码标记**：命令、环境变量名、工具名、参数名、文件路径、HTTP 状态码与配置字面量一律使用行内反引号 `` ` `` 包裹；多行代码块必须标注语言标识符（如 `bash`、`powershell`、`json`、`toml`、`ini`、`text`）。
4. **链接校验**：仓内文件跳转统一使用相对路径链接，提交前确认所有相对链接目标真实存在，且未指向被 `.gitignore` 忽略的本地目录（如 `dev/`、`.reference/`、`.runtime/`、`artifacts/`）。
5. **隐私与卫生**：公开文档与配置示例中严禁出现真实 Token、私有代理地址、个人宿主机用户名或绝对路径。
