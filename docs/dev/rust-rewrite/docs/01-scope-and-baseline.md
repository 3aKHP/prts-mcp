# 完整复刻范围与固定基线

## 目标与完成定义

在本地 Linux 环境实现 TS/v2.8.1 的全部 24 个 MCP 工具、每个 action/scope、两种 transport、两种协议时代、数据同步、两个图片后端、配置与运维接口。实现应脱离 TS/Python 运行时独立工作，并具备搬入未来 3.x 主工程的结构。

“完整”同时要求：coverage.csv 所有必需行实现并验证；同一输入与数据下的结果通过 06 的比较规则；关键失败与恢复路径通过；GHCR 旧部署副本可启动、升级及回读；差异只有本节允许项或后来获得明确批准的登记项。测试通过数、代码量、24 个同名空壳工具都不能代替完成定义。

本地验收平台固定 Linux x86_64（当前 WSL2、Linux 容器）。Windows/macOS 路径规则须保留为可移植实现并做纯解析案例；未实际运行这些平台时明确列为未验证，不能声称跨平台分发完成。多平台发布不阻塞本地功能复刻，但会阻塞相应平台的未来公开支持。

## 基线规则

- TS 发布 tag 与 Python GHCR 参考 tag 都指向 `e0ba36096cdd46640166b0a5db02902fa9a6a24c`。
- 主 oracle 是此提交的 TS，在 Bun 1.3.14 运行。Node 24.18.0 是本机可用的辅助入口验证运行时；发布 package 的 Volta 提示为 24.14.0，不冒称两者相同。
- 固定提交的 `package-lock.json` 和 `bun.lock` 分别用于对应安装。P0 记录解析后依赖树；不要用外层 develop 的 package.json 替换 oracle。
- 当前外层 develop `fbfb695` 与发布 tag 的源码/测试相同，仅六个版本及 CHANGELOG 文件有差异。这使当前提取的源码声明可核对，但不授权执行时继续依赖移动工作树。
- `.reference/ts-v2.8.1/` 是冻结源副本，来自 `git archive`；不改它修复 oracle。必要的网络录制适配器放在 harness，明确记录每个替换点。
- 后续 2.x bugfix 只加入待移植登记，不能静默刷新基线。升级基线需要维护者明确决定，并重跑受影响案例。
- P0 固定 GameData excel、levels、story、图片代表资产、manifest 与 Wiki 响应；保存 SHA-256、来源、版本、捕获方式。数据包版本与服务器版本是不同轴，不要求所有资产发布日期等于 2.8.1。

## 什么必须精确，什么允许不同

| 编号 | 边界 | 处理 |
|---|---|---|
| C-01 | 工具名称、参数、required/default/null、枚举与数值边界、中文描述 | 对齐发布声明和实际 SDK 验证；不能用更严格 Rust 类型悄悄缩小输入范围 |
| C-02 | 成功 Markdown、项目自有错误文字、图像内容、字段值、数组顺序、分页/截断 | 固定数据下精确比较；JSON 对象键序本身不比较，但键序影响渲染时必须保留 |
| C-03 | structuredContent / content / isError、JSON-RPC 与 HTTP 错误层级 | 保留字段存在性、类型和代码；不能把文字降级改成异常 |
| C-04 | 配置、会话、同步、恢复、文件互操作 | 比较可观察行为与状态不变量，不照搬内部调用次数 |
| D-001 | 构建身份与非确定值 | 服务名保留 `PRTS_Wiki_Assistant`；Rust 版本 `0.1.0+ts2.8.1.local`，不伪装正式 2.8.1。PID、端口、时间戳、session ID、随机目录名按绑定关系比较 |
| D-002 | 原生诊断 | 已获维护者批准。保留端点、鉴权、通用计数；Rust 指标 schema 见 04。不能把 JS heap 填零冒充同一指标 |
| D-003 | 依赖产生的错误详情 | 已获维护者批准。只归一化被案例明确标出的底层详情；错误码、字段定位、项目文案前缀与是否失败仍严格比较 |
| D-004 | 本地分发载体 | 私有 Rust 包和本地 npm 薄包装、镜像名称不同；保持入口行为。无 npm/PyPI/GHCR 正式发布，多平台状态单独披露 |

D-001/D-004 是本地实验身份及分发范围，不允许借此更改客户端业务结果。用户明确要求的 GHCR 差异是入口 profile，而不是 D-002 的额外业务豁免。

## 冲突与 bug 裁决

执行优先级：本次维护者明确决定 → 本簇已批准的兼容边界 → 固定 TS 源码加同条件实测 → 对应测试/fixtures → 既有叙事文档。源码与实际行为冲突通常来自依赖或运行环境，应先复现。不能通过只读源码宣布 wire 行为。

已经核对：`list_stories.include_summaries` 默认 **false**；旧 STATUS/ROADMAP 中的 true 不作为基准。`SESSION_IDLE_TIMEOUT_MS` 允许正有限十进制小数/指数；`PRTS_METRICS_ENABLED` 只接受原样 `true`。其他布尔开关不能套用这个严格规则。

内部 bug 且修复不改变本簇外部契约：直接修、记录理由并验证。业务可观察 bug：默认复刻并登记；若涉及数据破坏、安全边界或无法安全复现，隔离该案例、提交决策，不复制危险动作。不能以“3.x 是 major”自行授权差异，也不能以“完全复刻”为由明知存在危险仍执行它。

新问题登记最少包含：ID、固定版本的复现、TS 观察、Rust 预期、影响面、是否阻塞、维护者决策和验证案例。未决差异不能计为 accepted；继续其他独立任务。

## 明确不包含

管理 CLI、TOML 配置体系、SQLite、工具重新设计、新数据域、Python 业务 parity、1.7 LTS 32 工具、公开渠道切换均不属于此复刻。可设计清晰模块边界以支持未来 CLI，但不提前实现 doctor/config/data 子命令。历史兼容 shim 没有运行时消费者时不必复制。
