## 交付范围与证据

### 1. docs/04 环境变量与入口 profiles 补齐

- **入口 profiles（4 类，docs/04 表逐行）**：
  - `prts-mcp-rust`：默认 HTTP，`--transport http|stdio`；新增内部 `--bundle-root <dir>`（非公共环境变量）。
  - `prts-mcp-ts` / `prts-mcp-ts-bun`：HTTP，不读 PRTS_TRANSPORT、无 CLI 切换。
  - `prts-mcp-ts-stdio`：仅 stdio，绝不监听端口。
  - `prts-mcp`（GHCR 兼容）：PRTS_TRANSPORT 先 trim+lowercase，仅 `http` 选 HTTP，否则 stdio。
- **PORT 语义按 profile 分裂**（oracle 探针钉死，见下）：
  - TS profile = JS `Number(PORT)`：`0x10`→16、`1e2`→100、`""`→0、`3000.5` 保号但绑 3000、`70000` 日志原样但绑 65535、`abc/-1/0` → NaN/负/0 绑**临时端口**，永不退出。启动日志逐字回显 Number 字符串（`NaN`、`3000.5`…）——与 bun dist 实测逐条一致（/tmp 探针 8 值 + ss 实绑验证）。
  - GHCR profile = python `int(PORT)`：仅 HTTP 分支解析（stdio 完全不读）；`[+-]?数字` 允许首尾空白；非法值 `PORT must be numeric, got 'abc'. Exiting.` 退出 1；越界值 bind 失败退出 1。
- **信号/EOF/退出**（oracle 对照：TS 无信号 handler，默认信号终止）：
  - 不安装 handler，与 oracle 一致：SIGTERM/SIGINT 即时信号终止（实测 <5ms，同步重试梯已武装也不阻塞——"不把下载完成作为关闭进程的前置条件"）。
  - stdio EOF → 0（保持 P1 契约，重试梯 armed 下复测）。
- **Windows LOCALAPPDATA**：`windows_default_gamedata` 纯解析函数 + 单测（含 `??` 语义：空串不是 unset）；Linux 实机不冒称通过（docs/04 规则）。
- 其余变量族在 P1–P6 已落，本阶段以单测+进程测试复核（GAMEDATA_PATH 空串仍 custom、STORYJSON_PATH 空串仍同步、XDG 空值、GITHUB_MIRRORS trim/去尾斜杠、SESSION_IDLE_TIMEOUT_MS 严格十进制、PRTS_OUTPUT_CHANNEL、PRTS_DEBUG_TOKEN 空值=禁用、PRTS_METRICS_ENABLED 仅原样 `true`）。

### 2. 诊断端点（D-002）与迁移映射

- `/health` = `{"status":"ok"}`（不变）。`/debug/cache`、`/debug/metrics`：
  - 认证：`Authorization: Bearer <PRTS_DEBUG_TOKEN>`，等长检查 + 常量时间比较；未配置 token（含空串）/缺失/错误一律 **404 文本 `Not Found`**（Express sendStatus 逐字）。
  - metrics 关闭与认证失败**不可区分**（同为 404）；`PRTS_METRICS_ENABLED` 仅原样字符串 `true` 生效（TRUE/1/空/yes 均 404）。
  - 不记录参数、结果、session ID、认证或图片 base64；token 不出现在任何诊断输出。
- **/debug/metrics 新 schema（`prts-mcp.rust.metrics/v1`）**：保留 `server.version/uptime_ms`、`requests`、`tool_calls`（含 by_name）、`sessions`、`cache` 组织；`process` 只含真实 `rss_bytes`、`rss_high_water_bytes`（/proc/self/statm 与 /proc/self/status VmHWM）+ `runtime:"rust"`；删除 V8 堆字段（不填 0）。duration 字段保留毫秒小数（f64 CAS 累加）。tool_calls 标签只允许注册工具名。
- **/debug/cache 迁移映射**（旧子键 → 新子键）：

  | 旧域.子键 | 新域.子键 | 说明 |
  |---|---|---|
  | operator.character_table / handbook_table / charword_table / name_to_id | 同名 | 1:1；handbook/charword 计数沿用 TS 覆盖（handbookDict/charWords 键数） |
  | enemy.enemy_handbook / enemy_database / enemy_name_to_id / enemy_search_records | 同名 | 1:1；enemy_handbook 计数 = enemyData 键数（TS 同） |
  | stage.stage_table / zone_table / stage_search_records | 同名 | 1:1；zone_table None = loaded-null（loaded:false count:0） |
  | stage.**stages_map**（新增） | stage.stages_map | Rust 专有：list_stages 每代构建一次 id 序 map 视图（TS 每次内联排序）；因此 stage_table 的 hits 低于 TS 口径（每代一次 miss，后续调用命中 stages_map）——真实缓存差异，如实暴露 |
  | stage_enemy.enemy_appearance_index | 同名 | 1:1 |
  | item.items / item_lookup / item_search_records | 同名 | 1:1；item_lookup 计数 = map size |
  | search.search_records | 同名 | 1:1 |
  | building.building_table / building_skill_records | 同名 | 1:1；building_table 计数 = buffs 键数（TS 覆盖同） |
  | skill.skill_table / skill_search_records | 同名 | 1:1 |
  | story_search.story_search_index | 同名 | 全局共享索引（按 zip stat 身份缓存）：命中=hit，换包重建=miss+clears+1；Rust 在 gamedata 换代而 zip 未变时保持命中（TS activation-clear 后必重建）——计数口径差异，已说明 |
  | images.char_skins | 同名 | 1:1（每代 dataset 缓存） |
  | artwork_mediawiki.image_cache | 同名 | 256MiB LRU 真实命中/未命中；loaded=size>0；bytes=当前占用 |

  语义约定：hits/misses 为进程生命周期累计；loaded/count/clears 描述**当前代**（activation 换代 = TS registerActivationListener(clear) 的可观测量：clears+1、loaded 复位）。埋点全部挂在真实缓存路径（`Datasets::get_or_load_counted` 21 槽 + story 索引 + 图片 LRU），未计数的路径显示诚实的 0，不伪造。

### 3. Bundle fallback 与可重定位布局

- `RuntimeConfig::from_env_with_bundle()` 解析 bundle root：`--bundle-root` 参数 > Docker（`PRTS_MCP_ROOT == "/app"` → `/app/data`）> 原生布局（exe 父目录的 `data/`，即 `bin/` 与 `data/` 同级）。编译机绝对路径不入二进制；不新增公共环境变量。
- 生效语义 = TS loadConfig 的 BUNDLED_* 半边：同步路径不完整时才兜底；bundle 侧同样走 pair 指针 → extract_meta → 完整性门；story 链 = 配置路径 > `/data/storyjson/zh_CN.zip` > bundle zip。
- dev 树（target/release）无相邻 data/ → 无 bundle，与 TS dev 布局一致（差分回归 383/383 不受影响）。
