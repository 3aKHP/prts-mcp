## 交付

### 1. 工具与声明（23/23 契约位）

- `search_prts`（S 工具，三通道）：query/limit 1..20 默认5/search_mode enum 默认 text/filter_technical 默认 true；结构化 payload + 渲染文本；domain 校验文案与 `搜索 PRTS 失败：` 前缀分层。
- `prts_page`（T 工具，全通道纯文本）：action 必填 enum（read/sections/categories/links/template）、section_index **optional int（null 拒绝——探针）**、direction enum 默认 outbound、limit 1..100 默认 30；read 的"未找到或内容为空"与 sections/categories/links/template 的"未找到。"错误分层；模板渲染失败固定建议文案。
- 声明字节取自 contracts/tool-declarations.json；**注册顺序修正为 oracle 实测顺序**（prts → gamedata → story → artwork@P6）——由延迟的全工具面 tools-list golden 对齐发现并修复（177 项差异 → 1 项计数差异）。
- dispatch 插槽改为 boxed-future 异步（`DispatchFuture`/`tool_async!`），21 个同步 dispatcher 宏包装零改动；两个 Wiki dispatcher 为首个异步消费方。

### 2. Wiki 客户端（src/wiki/client.rs）

- 节流：模块级 `nextAllowedTime` 对应物——**先占槽再等待**；并发保留各自 1.5s 槽位（单测以 6 并发×120ms 实测最小间隔断言）。redirect 跟进与模板批量 POST 均过同一节流器（与 oracle 一致）。
- 每请求 15s 超时（tokio timeout）；非 2xx → `PRTS API error: HTTP <status>`。
- 网络环境：reqwest `system-proxy` 特性 + `NODE_EXTRA_CA_CERTS` 根证书钩子——与 bun（小写 `https_proxy` + NODE_EXTRA_CA_CERTS）**同源同值**，回放与 live 双验证。
- 运行时错误文案探针钉死（bun 1.3.14）：连接失败 `Unable to connect. Is the computer able to access the url?`；坏 JSON `Failed to parse JSON`；超时 `The operation timed out.`。Rust 侧以常量对应，差分逐字节一致。

### 3. 文本管线 = QuickJS 内嵌 oracle 原文（src/wiki/text_ops.rs）

`unescapeHTMLEntities / cleanSnippet / stripHtml / isTechnicalPage / isRedirectLike` 的 TS 源码**原样**运行于每线程 QuickJS VM（值参传递、无源码拼接；与 `regex_compat` 同一安全姿势）。探针单测修正三处想当然预期（REDIRECT 仅删标记、RLQ 正则止于首个 `)`、`spine` 须以分隔符结尾）——以 oracle 实测行为为准。`stripWikitext` 复用 P3 sanitizer 端口（片段预处理顺序 stripWikitext → unescape → cleanSnippet 与 oracle 一致：转义 HTML 变字面文本保留）。

### 4. 模板链（src/wiki/template.rs + template_xml.rs）

- **宽容 XML 解析器**：fast-xml-parser preserveOrder 行为等价——错配闭合标签接受（隐式闭合）、EOF 未闭合自动收、`garbage <<<<` 抛错、空串得空文档；四条行为均对 oracle node_modules 内 FXP 实测。实体解码（5 命名+十/十六进制）。
- **wikitext 重建**：template `{{名|…}}`、tplarg `{{{名|…}}`（**三开二闭——对 dist 实测的 oracle 怪癖，源码误读三闭已被探针纠正**）、link `[[目标|…]]`、comment 元素/注释节点还原 `<!--…-->`；`<ext>` 等不支持节点 → `不支持的模板字段节点：ext。`。
- **needsRender 判定**：`<comment>` 元素在跳过表（实测：值内 wikitext 注释不触发批量渲染）；空值丢弃；位置参数（name 缺失或带 index 属性）。
- **批量渲染**：`PRTSMCP_<uuid32>_BEGIN_<i>_` 标记协议单 POST；响应校验链（请求失败/格式无效×3/结果为空/边界无效×3）；marker 顺序稳定排序校验；切片 trim；**标记不泄漏**（单测断言 + live 真实渲染输出核对）。
- 装配：`_positional`/`_comment`、同名模板后者覆盖、空条目不入结果；JSON 文本 = `JSON.stringify(templates, null, 2)` 对应 serde_json pretty（UTF-8 字面、2 空格）。

### 5. 回放差分装置（tools/wiki-replay.mjs + contracts/wiki-replay/）

- **MITM 代理**：openssl 本地 CA + SAN(prts.wiki/media.prts.wiki/localhost) 30 天证书；CONNECT 隧道 TLS 终结（ALPN http/1.1——rustls 必需而 bun 宽容）；一次一请求 Connection: close。
- **脚本化规则**：GET 规则**精确参数集匹配**（请求形状进 golden——srwhat/srlimit=2×limit/srprop=snippet|redirecttitle 等均被对端核对；"不改用 extracts" 由 `prop=text` 规则反证）；POST 规则子集匹配（`text` 带随机 marker 无法预编）+ `render_segments` 动态回显（prefix/suffix 包裹、scramble/drop_end/empty 注错）。
- **故障注入**：死代理端口（连接拒绝）、HTTP 500、坏 JSON、15.5s 延迟（oracle 15s 超时分支）。
- **发现并修复的装置侧问题**：node24 ALPNProtocols 须字符串；openssl SAN 经 `-extfile` 而非 stdin（无 SAN 被 rustls 拒绝）；spawnSync 冻结事件循环导致代理假死（测试姿势问题，非装置问题）。
