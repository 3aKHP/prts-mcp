# Rust 迁移真机 E2E

全量真机验证对高风险变更强烈建议，通用工作流仍由维护者按 WORKFLOW.md 裁量。本次 3.0 迁移已明确选择在 M4 完成一次完整流程；M1B 离线对照、原生 process tests 和镜像/生命周期测试不能代替这一验收。

M4 使用 M3 生成的实际候选原生/npm/Docker 发行物，启动真实 MCP 客户端（本机 Windows 和/或 WSL）。Linux arm64 和 macOS 的原生平台安装/运行证据来自 M2 对应 runner，WSL 不能替代这些证据。

1. 隔离旧 2.8.1 与新候选的端口和数据卷，记录版本、平台、二进制校验值、客户端和配置。保留旧测试卷副本，禁止触碰用户真实卷。
2. 验证新主命令默认 HTTP、显式 stdio、旧三个命令和 GHCR 默认 stdio；覆盖 legacy/modern 握手、会话/鉴权、输出通道、EOF/信号/关停。
3. 完成自然同步：GameData excel/levels、StoryJson、立绘两条路径及增量链；检查代际激活、共享锁、缓存失效、离线重启与恢复。
4. 真实客户端调用全部 24 工具，覆盖各工具组和数据缺失/非法输入/网络失败。保留脱敏的可复现证据。
5. 在旧卷副本上执行升级；用固定旧发行物回读 Rust 使用后的副本，验证回滚。不能以“数据格式未主动修改”代替回读实证。
6. 修复迁移阻断问题并复验；报告每个平台/环节的通过、失败或未执行情况。

实际候选已固定为 3.0.0-alpha.3；外部 Agent 的步骤、入口、缓存位置及流量安排见 [M4 执行计划](plans/3.0-m4-execution.md)。本机 Windows Clash 对 WSL 全部出站做规则代理，实际 GitHub 访问会计费，清空代理变量或 --noproxy 不构成免费直连。优先复用真实数据，GameData 原始 ZIP 和立绘本地重建包经受控镜像回放，真实源尝试在本地失败代理处失败，公网只做少量必要调用；原始上游下载、真实图片、合成 fixture 的证据不得混写。本计划不增加独立验证门禁，也不将全量 E2E 变成例行发布步骤。历史双实现 E2E 流程保存在 [legacy/2.x/E2E.md](legacy/2.x/E2E.md)，对旧线仍以其自身 LTS 文档为准。
