# ADR-0003：3.x 管理 CLI 的范围与时序裁决

- 状态：Accepted（补录）
- 决策日期：2026-10-13（初始评估记录于 2026-10-11）
- 关联：[3.0 统一技术栈选型档案](../../archive/3.0-unified-rust-stack-assessment.md)、[ROADMAP.zh-CN.md](../../../ROADMAP.zh-CN.md)、[STATUS.zh-CN.md](../../../STATUS.zh-CN.md)

> 补录说明：本决策冻结于 ADR 目录建立之前（3.0.0 筹备期），因管理 CLI 是进行中的 Post-3.0 主题、未来开题需要防止重复论证，按本目录的补录例外整理自决策期间的内部评估记录。

## 背景与问题

评估要回答的问题是：是否在 3.x 引入独立的管理 CLI（配置与诊断子命令体系），何时做，以什么形态做。当时 2.x 双实现的配置体验有五个记录在案的痛点：

- 环境变量联动不直观（例如 `GAMEDATA_PATH` 只要存在即关闭游戏表自动同步，即使赋空值）；
- 入口不一致：Python 经 `PRTS_TRANSPORT` 选传输，TS 经不同 bin 选择；
- 实际生效值不透明：无法判断配置来源与覆盖关系，也无法解释同步为何未运行；
- 配置读取分散在多个模块，部分发生在模块加载时；
- 缺少无副作用的排查入口：没有一个不启动服务、不下载数据即可检查配置、权限与数据状态的命令。

公开佐证：[环境变量参考](../../admin/environment-variables.md) 现登记 27 个运行时环境变量。

## 备选方案

- **在 2.x（Python + TS 双实现）各做一套管理 CLI**：否决。会扩大统一技术栈时需要复制、兼容和迁移的行为面。
- **管理 CLI 纳入 3.0.0 迁移首发**：否决。3.0 专注技术栈统一与分发平滑切换，不能反过来强迫 Rust 原型先完成完整管理平台。
- **把每个环境变量简单映射成一个命令行参数**：否决。不解决来源解释、优先级与生命周期问题，反而增加维护面。
- **推迟到 3.0 之后另行开题，先定义语言无关契约，最终由唯一的 Rust 实现持有配置与命令契约**：采纳。
- **过渡期允许 Rust 实验保留最小开发参数入口**：采纳但带限制——该入口（现 `src/bin/prts-mcp-rust.rs` 的 `--transport`）不是正式 CLI 契约，不得悄悄扩展为第三套受支持接口。

## 决定

1. 管理 CLI 不纳入 3.0 迁移首发，迁移完成后另行开题。
2. 2.x 不开展管理 CLI 产品实现，继续使用已支持的启动入口与环境变量。
3. 3.0 迁移只保留启动入口与环境变量，不新增配置文件体系或管理命令。
4. 管理 CLI 的框架选择与实现另行开展，不占用迁移首发范围。
5. 既有 2.x 配置错误、文档缺陷与安全问题仍可修复，不因 CLI 延后而停止维护。
6. 内部评估产出的设计储备（候选命令方向、优先级建议、验收维度）保留为后续开题输入；首期范围、配置格式、命令命名、热更新能力与旧变量长期支持均未冻结，本文不作承诺。

## 后果

正面：

- 3.0.0 于 2026-10-16 按既定门禁发布，无 CLI 范围蔓延（[CHANGELOG.zh-CN.md](../../../CHANGELOG.zh-CN.md)）。
- 入口兼容目标达成：四类入口的默认传输与切换方式完整保留并成表（[2.x → 3.0 迁移指南](../../migration-2.x-to-3.0.md)）。
- 决策当日即落实公开口径：ROADMAP 声明管理 CLI 与新功能后置；发布后加入 Post-3.0 Backlog（`--version`、`--help`、缓存与同步状态检查级别）。
- 实现现状与决策一致：`src/bin/` 下各入口均为薄启动器，产品入口 [prts-mcp.rs](../../../src/bin/prts-mcp.rs) 只读 `PRTS_TRANSPORT`，唯一参数解析在开发入口。

负面与代价：

- 3.1.x 用户仍只能以环境变量配置，排查依赖 `/debug/*` 端点与 stderr 日志。
- 公开承诺口径（`--version` / `--help` / 状态检查）显著窄于内部设计储备，两者差距至今未对齐。
- 管理 CLI 至今无任何版本承诺；未来开题时应以本文与内部设计储备为输入，避免重新论证已否决的方案。

备注：开发侧的贡献者评测工具已有一个 `doctor` 子命令（见 [COMPARATIVE-EVALUATION.md](../COMPARATIVE-EVALUATION.md)），属开发工具而非产品 CLI；未来产品命令命名需与之区分。
