# ADR-0013：3.0 文档体系重建与 DOCUMENTING.md 的诞生

- 状态：Accepted（补录）
- 决策日期：2026-10-15（维护者于 2026-10-13 将其设为正式发布门禁，2026-10-14 执行）
- 关联：PR [#244](https://github.com/3aKHP/prts-mcp/pull/244)（merge `8812142`，主提交 `35c8285`）、[DOCUMENTING.md](../DOCUMENTING.md)、[docs/README.md](../../README.md)、[docs/archive/](../../archive/README.md)

> 补录说明：本决策落地于 ADR 目录建立之前（3.0 发布窗口），其产物（含本文的写作规范）至今现役，按本目录的补录例外整理自决策期间（2026-10-13 至 2026-10-15）的内部工作记录与公开 git 历史。

## 背景与问题

3.0 的 M1B 里程碑把仓库根目录切换为纯 Rust 工程（commit `a5cad51`，PR #228）：移除 `python/`、`ts/` 的同时，公开文档被大幅压缩为占位存根，原文移入存档。当时的盘点（行数口径）：根 README 271 → 约 50 行、CONTRIBUTING 66 → 9 行、STYLE.md 400 → 23 行、E2E.md 138 → 14 行、ENVIRONMENT.md 106 → 33 行、CD 恢复手册 74 → 7 行。

存根态的具体病灶：过时事实残留（发布状态停留在中期里程碑、CD 手册称“尚无 Rust 公开发布”、贡献指南仍按双实现锁文件要求）；`python/docs/deployment.md`（318 行）等完整指南未迁移；根 CHANGELOG 只剩 3.x 条目，0.x–2.x 历史仅存在于 tag 与档案；STATUS/ROADMAP 缺发布摘要与已交付记录。

维护者因此在 2026-10-13 把文档工作设为正式发布的阻断门禁，并明文禁止两种敷衍做法：只保留简短入口、把历史归档当作当前说明。

## 备选方案

以下否决均有当时记录：

- **维持存根现状**：否决（门禁原文“不能只保留简短入口”）。
- **以历史归档链接替代当前说明**：否决（“把历史归档当作当前说明”不可接受；专项计划重申“只把文件放回历史档案、用一条链接替代原有完整说明，不能视为恢复完成”）。
- **恢复但沿用旧实现的事实**：否决。专项计划列出必须按 Rust 实际校正的事实清单（发布状态、运行要求、传输默认值、备用数据、图片网络措辞、兼容证据范围、维护政策），并禁止借润色改变产品契约。

事后推断（无当时文字记录，如实标注）：GitHub Wiki、集中式单一手册、外部文档站点等载体形态未见任何讨论记录，“仓库内 Markdown + PR 评审”是默认前提而非被权衡的选项；读者角色分层与单一事实源表随重建直接落地，也没有“单一大手册”等替代结构的评估记录。

## 决定

以 PR #244（分支 `docs/v3.0.0-documentation-restoration`，merge 口径 114 个文件、+6628/−13632）落地：

- **读者角色分层**：`docs/` 分为 `user/`（客户端用户与创作者）、`admin/`（服务端部署运维）、`dev/`（贡献者与发版维护者）、`archive/`（里程碑技术档案）四板块，迁移指南 `docs/migration-*.md` 居顶层，[docs/README.md](../../README.md) 作总目录按角色导航。user/admin 边界在维护者精校阶段才定型（部署指南与环境变量参考由 user 改入 admin）。
- **单一事实源**：[DOCUMENTING.md](../DOCUMENTING.md) 建立“文档位置 → 目标读者 → 核心职责”对照表；同一事实只在最贴近读者任务的权威文档维护完整细节，其余文档只给简述与跳转链接。
- **写作纪律**（创建提交 `35c8285` 即全部存在，此后条款零改动）：`docs/` 下各文件中文单语（仅根核心文档双语）；每个自然段/列表项写成单行物理行；中文散文用全角标点与弯引号、代码用 ASCII 直引号；公开文档禁止链接 `dev/` 等 gitignored 目录、禁止真实 Token 与私有地址；反“AI 腔”三条（禁电报式压行、禁预防性免责语调、读者适配信息层级）；核心事实核对表；AI 协作者分工（事实核对与撰稿分离）。
- **规范来源**：以维护者另一项目 [QuickQuip 的既有写作规范](https://github.com/3aKHP/QuickQuip/blob/c00f3d27bcf81d2e677bc6bc0cf397f0d38a0c2f/docs/dev/documenting.md)（读取时提交 `c00f3d27`）为底稿做本地化。
- **历史连续性**：根 CHANGELOG 补回 48 个 0.x–2.x 版本入口（双实现相同条目合并、差异按实现标注）；新增 CHANGELOG/STATUS/CONTRIBUTING 的简体中文副本；[docs/archive/](../../archive/README.md) 新建 1.0–3.0 里程碑档案；开发计划与原始验收报告移出公开树。

## 后果

正面：

- 文档门禁收口，同日进入 3.0 正式发布的最后里程碑；3.0.0（2026-10-16）携重建后的文档体系发布。
- DOCUMENTING.md 自此成为全部公开文档（含本 ADR 目录，`adr/README.md` 规定文风遵循 DOCUMENTING.md）的强制规范；其后续修改均为事实行维护（候选版本号与后端措辞），写作纪律条款零改动。
- 验收口径（当时记录）：46 份文档链接与代码栅栏检查通过；91 份移出文档与本地存档逐字节一致；32/32 份 2.8.1 基线原文在树中逐字节可读；首轮自查 25 份文档修正 18 份。评审按 Standard 流程完成（独立干净上下文只读复核，初审 3 项 Should-fix 经修正后闭环，无 Blocking）。

负面与代价：重建集中消耗了发布窗口内约两天的维护者精力；user/admin 边界直到精校阶段才定型，说明分层标准在启动时并不完备。

遗留事项与材料缺口：

- 载体形态（wiki/外部站点等）无备选讨论记录（见“备选方案”节标注）。
- 文档重建无专门 CHANGELOG 条目，公开记录只有 PR #244 与提交本身。
- 内部记录中“外部 Agent 精修”环节未实际开展，精校由维护者人工完成；PR 页面上的讨论未存档于本地。
