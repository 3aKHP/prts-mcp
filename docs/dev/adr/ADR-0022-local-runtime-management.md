# ADR-0022：本机运行实例管理与 systemd 托管

- 状态：Accepted
- 决策日期：2026-11-03
- 关联：[ADR-0021](ADR-0021-management-cli.md)、[CLI 指南](../../admin/cli.md)

## 背景与决定

维护者决定继续在 3.2.2 中加入服务生命周期和运行中实例管理。推荐部署采用 Cargo 安装原生程序、systemd 托管；已有 npm 启动桥部署继续受支持。本决定扩展 ADR-0021 的后续工作范围，不改变其离线命令契约。

`prtsctl service` 管理 systemd unit，`prtsctl runtime` 连接运行实例。原有 `config`、`doctor`、`data` 命令保持本地调用含义。服务启停由服务管理器执行，运行进程不自行实现守护或重启策略。

本机控制通道显式启用，默认关闭。Unix 使用用户私有目录中的 socket 与对端凭据；Windows 使用受限 ACL 的本地 named pipe，拒绝远程管道。服务用户和管理员拥有管理权限，不将诊断 Token 升级为写权限，不在公网 MCP 路由加入管理操作。

实例映射只记录名称、端点和服务标识，不保存凭据。协议版本独立于产品版本，采用有界 JSON 帧。握手给出能力和每次启动的新标识；后续请求携带该标识，防止操作落到已重启的实例。客户端和服务端均检查实例身份；不通过端口扫描或 PID 文件猜测目标。

在线配置来自运行进程的启动快照并脱敏，不能由 CLI 自身的环境推断。新增报告沿用 `schema_version` 和稳定类型约定；不修改 MCP 工具及已有诊断端点的契约。

同步任务、取消及停止收尾复用既有同步内核。任务历史有界且仅保存在内存，进程重启后旧任务标识失效。热更新仅覆盖同步周期、GitHub 凭据和镜像：保留启动环境覆盖规则，完整校验后原子应用，其他生效差异要求重启。

## 3.2.3 配置集中补充

管理端点与实例名纳入统一 TOML 配置及启动快照，网络客户端同样消费解析后的代理与 CA 设置。环境变量保留兼容覆盖能力，推荐的 systemd 部署只指定配置文件并管理进程；实例映射仍只保存定位信息。热更新白名单不扩展，网络与管理通道变更要求重启。

## 实施与验证

按本机只读管理、systemd 适配、任务与停止协调、热更新四个增量实现，各自独立审查。首个增量只公开状态、配置与数据查询，其余能力随对应实现开放。

五平台实际进程验证覆盖协议隔离、身份检查、重启标识和端点生命周期。systemd 验证使用真实系统级与用户级服务。服务器 Dogfood 先使用独立实例；生产切换保持原数据卷与对外入口，并保留回滚路径。

## 后果

管理能力与安装渠道解耦，stdio 服务器也可接受独立本机查询。新增 IPC 协议和运行时可变状态需要持续兼容性测试。Windows 安全描述符转换所需 FFI 局限在专用平台模块；不增加通用提权服务、远程控制协议或持久化任务数据库。
