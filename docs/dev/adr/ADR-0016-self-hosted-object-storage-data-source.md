# ADR-0016：自建对象存储数据源（R2 主源 + COS 回退）的选型与实施搁置

## 背景与问题

2026-09 中旬，一次 GitHub 侧可用性事件导致数据分发全链中断（2026-09-15 至 2026-10-18，后以手动触发恢复；按 [ADR-0002](ADR-0002-lts-akdp-projection.md) 的既定口径，中断根因不在公开材料中归因）。事件暴露出三层影响：

- 新数据生产停摆：工厂仓与 1.7 投影 fork 的自动化均不运行。
- 存量分发停摆：已发布的 Release 资产随仓库不可达，实例连旧数据都拉不到。
- 已部署实例降级不中断：走 `offline_fallback` 以最后激活世代服务并按重试阶梯退避，属设计内行为（[数据同步与存储管理](../../admin/data-and-sync.md)）。

同时记录在案的机制分析：既有逃生机制救不了这类事件——`GITHUB_MIRRORS` 是网络层代理，直连返回 404 时按 fail-closed 语义短路、不试镜像；Release 发现层仓库不可达时走不到下载环节。推论是需要独立于“镜像代理”语义的“数据源基址切换”能力。另一半动机是结构性的：数据工厂、分发、本仓库 CI 与投影 fork 全部收敛在单一维护账号上，单点结构被一次账号级事件实证。

当时记录的硬约束：数据契约 `prts-mcp-data/v1`（manifest 的 SHA-256 与 size 校验）不变，对象存储的 ETag 不得替代 SHA-256（其值为 MD5 或分片拼接格式）；图片增量链 fail-closed，自建源的保留起点必须覆盖舰队中最老客户端的基线；manifest 校验失败继续用上一代激活数据（既有行为天然适配）。

## 备选方案

以下裁决除标注外均有当时书面记录：

宿主层（工厂跑在哪、分发放哪）：

- **既有云 VPS 兼跑工厂**：否决其工厂宿主资格。实测余量不足，重采样负载会长时间打满 CPU 并给同机生产服务带来 OOM 风险；只适合做分发端且需保留策略。
- **维护者工作站跑工厂**：当时唯一已验证可跑全量工厂的环境；弱点是非全天候在线——故工厂留工作站、分发交给对象存储。
- **对象存储作分发端**：采纳。无服务器概念、按量计费，与不可变世代资产天然适配。

对象存储选型层（定价均为 2026-09 刊例价快照）：

- **Cloudflare R2**：采纳为主源。出口流量零费用且无上限、免费层覆盖起步阶段、自定义域名自带边缘缓存（不可变世代资产适配长缓存与 immutable 语义）、持久性指标满足归档要求。
- **腾讯 COS**：采纳为国内回退源。已有账号与实名、S3 兼容（同步工具零改动）、大陆直连稳定、与既有 VPS 有同地域内网亲和。
- **七牛 Kodo**：备而不选（第三选项）。免费层形态最接近 R2，但测试域名有回收期，长期外链必须绑已备案域名。
- **AWS S3**：不选。相对已选项无优势。
- **阿里 OSS**：列入比价表但未留下单独的取舍记录（材料缺口）。

域名策略（当时记录）：COS 侧复用现有已备案域名的子域（同接入商内换服务，零备案流程）；R2 侧不复用备案域名（其自定义域名要求整个 DNS zone 托管，迁 NS 有备案合规风险），另注册低价海外域名专用，顺带避免资产再次集中于单一主体。

既有机制再利用：否决。镜像级联救不了仓库级 404（见“背景与问题”），新开关必须是独立路径，不动既有 fail-closed 语义。

事后推断（无当时记录，如实标注）：“事件解除即无需自建源”这一选项没有留下当时的书面权衡；从事件最终走向看实际路径即如此，但不能反写为当时的裁决。阿里 OSS 未入选的合理解释可从比价表结构推断，无当时文字。

## 决定

采纳的目标架构（设计已冻结，未实施）：

- **拓扑**：工作站跑工厂，经 S3 兼容工具双写 R2 主源（出口零费用）与 COS 国内回退源；两源同构桶布局——`/catalog.json` 为唯一 mutable 对象（短缓存），`/releases/data-*`、`/releases/datarev-*`、`/images/<tag>/` 均为不可变世代资产、长缓存。
- **契约**：`catalog.json` 对齐 `prts-mcp-data/v1`（release 列表加资产 SHA-256 与 size），不模拟 GitHub API 响应形状；SHA-256 校验体系不变，ETag 仅用于 HTTP 条件请求。
- **客户端行为**：默认源不变（GitHub Release）；`PRTS_DATA_SOURCE_BASE` 未设置时行为与现状逐字节一致。
- **运维分层**：生产数据路径只走同步工具加桶级密钥（不引入 LLM）；运维杂务走最小权限、可撤销授权的 API 路径；控制台操作留给人。红线：已发布世代对象永不覆盖，修正走 `datarev-` 新对象。
- **实施清单（当时定级，全部未做）**：双实现 `sync/` 层加 `PRTS_DATA_SOURCE_BASE`（发现层读 `<base>/catalog.json`，下载层按 base 拼 URL）；工厂仓 publisher 后端抽象（`gh-release`/`static-push` 双后端，catalog 由 static 后端产出）；环境变量文档增补。定级为 Standard 变更、双轨评审、合并前做 sync/ 域真机验证。
- **搁置**：调研落档时三项定案前置均为“等事件解除后定案”；配套运维调研状态为“待账号开通后实施”。

## 后果

正面：

- 设计冻结使恢复实施不需要重新选型；公开路线图上已有对应承诺锚点（[ROADMAP](../../../ROADMAP.zh-CN.md)：“数据容灾与 AKDP 协同：多源对象存储备份镜像及图片分片进一步优化”）——同时构成“决策已作出但未兑现”的公开张力，本 ADR 的 Deferred 状态即是对该张力的如实登记。

负面与代价：

- 单账号单点结构至今维持；事件解除后未重新评估，搁置从被动等待转为事实上的无限期延后（无书面记录，如实标注）。
- 调研记录的实施位置已被 3.0 Rust 化淘汰：原文写的是双实现时代 `python/`、`ts/` 的 sync/ 层，主线现为 [src/sync/](../../../src/sync/)（Rust 单实现）；契约层结论不受影响，但恢复实施时变更面须按 Rust 树重估。

恢复实施的前置条件（凭材料可列出）：

1. 枚举工厂仓 `data-*`/`datarev-*`/`images-*` 全量历史 Release，再定“精简 vs 全量镜像”（事件期间无法列举）。
2. 定夺工厂仓与本仓库迁往 GitHub 组织的长期解（若迁，R2 路径降级为灾备双写：每代 Release 同步推 R2，下次账号级故障只需客户端切 base）。
3. 定夺 1.7 投影链存续方案：1.7 客户端只认两个 fork 仓的 `/releases/latest`，自建源形态下投影如何存续未决；当时记录的两条出路是由 catalog 生成器投影出 `/releases/latest` 兼容视图，或依托 EOL（2027-07-02，见 [ADR-0010](ADR-0010-lts-dual-maintenance-lines.md)）放弃 1.7 长尾。[ADR-0002](ADR-0002-lts-akdp-projection.md) 已将该问题公开登记为待定，本条为其承接处。
4. 开通对象存储账号并实测两个悬决点（授权能否限到单桶粒度；审计日志对对象级操作的覆盖度）。
5. 按双轨评审与 sync/ 域真机验证执行；落地时把架构与使用说明晋升为 tracked 文档。
6. 成本与网络数字为 2026-09-16 快照，恢复时须重新核实。

材料缺口：事件解除的确切日期无记录；三项“等解除后定案”悬项至今无后续；账号与桶/域名是否已建无记录；“不建自建源”选项无当时权衡记录。
