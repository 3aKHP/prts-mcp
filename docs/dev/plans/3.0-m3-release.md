# M3：候选发行物与发布流程

日期：2026-10-13。维护者授权进入 M3，确认可以操作 npm 账号 3akhp、@3akhp 范围及 2FA。M2C 已合并为 e58e646；本阶段不关闭 M4 运行门禁或文档专场，不推进稳定 latest，不发布 crates.io。

## 工作与验收

M3A 完成工程准备：Cargo/Cargo.lock 单一版本核对；五平台原生候选包加入已校验只读备用数据；在对应原生 runner 解压真实候选包、空 PATH/空用户目录查询与用户数据优先验证；汇总五份原生档案、九个唯一 npm tarball、双架构 Docker 档案及其实际来源/哈希/运行证据，生成可审核发行清单。所有共享 npm tarball 必须一致；缺平台、版本/源提交不同、包或证据缺失均失败。原 M2A SDK 保留独立输出，不把未携带完整备用数据的 SDK 冒充候选发行物。

M3B 完成发布流程及外部身份验收：固定 .github/workflows/release-rust.yml，GitHub-hosted runner 使用 Node24 与满足 OIDC 要求的 npm；发布环境 rust-release，npm OIDC、GHCR GITHUB_TOKEN 与 GitHub Release 使用同一经过验证的候选快照。包顺序为五平台及 data → runtime → 两入口。版本 tag 与 Cargo 相同，预发布仅 npm next / Docker 候选标签 / GitHub prerelease且make_latest=false；stable 在 M5 明确启用前拒绝发布。旧 npm/LTS publisher 和环境不替换，不改变旧分支 workflow。

首次实际公开候选版本、来源提交、九个包及渠道影响应先完成具体产物和独立审查，再由维护者确认。首次 npm 注册不能仅凭 E404 认领可用；没有账号权限或名称冲突时停止该渠道，不自动改名。产物验证与代码准备不依赖 npm 登录。

每包配置 GitHub owner=3aKHP、repository=prts-mcp、workflow filename=release-rust.yml、environment=rust-release。流水线计划直接 npm publish 并在必要的重试时管理 dist-tag，配置时须允许这两项；不能只保留默认暂存权限。GitHub environment 控制实际发布批次，npm OIDC 不需要长期 NPM_TOKEN。需要先核验既有旧线 trusted publisher，添加新身份时不删除旧身份，不擅自禁用会影响旧线的权限。

npm目前要求已有包才可建立trusted publisher；首次建立的新包需要维护者登录账号，使用审核后的真实产物。官方支持 npm stage publish 先建立并暂存，维护者2FA批准后公开；也支持维护者手动发布。采用哪个首次注册流程在实际产物形成后确认，不制作空占位包。首次人工建立的版本不作为 OIDC 成功证据；仍须用后续实际候选版本验证 OIDC。新publisher要求两天内首次成功使用，配置应与首次OIDC验证协调，不提前空等。

## GitHub/GHCR 配置

当前仓库为公开仓库，API身份具有admin权限；已有环境npm/pypi不变。新rust-release环境的名称与npm配置须一致，允许v3.* tag，人工审批者及tag保护由维护者设置或明确授权配置。main仍是旧2.x默认分支，M5前不把Rust源码整体移入main；新workflow手动dispatch的默认分支登记限制需要披露，发布tag和release分支的push使用该ref内的workflow。

GHCR沿用ghcr.io/3akhp/prts-mcp，发布job使用packages:write及GITHUB_TOKEN；实际操作前核验该既有package授予仓库Actions写权限。双架构manifest必须来自已验收的两份原生镜像；只查看manifest或仅模拟arm64不能代替原生执行证据。M5前不设置:3或:latest。GitHub prerelease不得覆盖GitHub Latest。

## 验证与收口

有意义的负测覆盖版本/tag混用、旧LTS/fork、dev/稳定渠道提前发布、缺失或冲突产物、校验清单外输入、版本/commit/pin不一致。执行完整Rust验证、workflow lint、五平台原生/npm/候选运行及双架构Docker；PR后独立clean-context只读审查来源/发布权限和实际候选/数据边界。Bot故障仍按维护者既有指示忽略。

M3A代码/CI通过只说明工程准备通过；环境、npm首包建立、OIDC真实发布、GHCR实际manifest及公开候选安装未验证时分别明确列为待办，不能把M3整体标完成。M3完整收口后才进入M4，不以自动流程执行M4或M5。
